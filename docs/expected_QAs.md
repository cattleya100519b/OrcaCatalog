# 想定問答集

## 
- なぜNext.js？
  - 現時点ではWeb版のフロントエンドとして採用している。  
    ReactベースでWebアプリを構築でき、今回必要な個体検索・詳細表示・写真登録などを比較的少ない構成で実装できるため。
- なぜSwiftUI？
  - iOS版についてはAppleの標準UIフレームワークであるSwiftUIを採用している。  
    iOSとの親和性が高く、写真・位置情報・MapKitなどAppleプラットフォームの機能を利用しやすいため。
- Androidは？
  - 現時点では専用アプリを作る前提にはしていない。  
    一般利用者向けであれば、まずWeb版でAndroidを含む端末をカバーする想定。  
    Androidアプリが必要になった場合は、その時点でReact NativeやFlutterなどを含めて検討する。
- WebとiOSを別実装する理由は？
  - 現時点では、それぞれのプラットフォームに適したUI・機能を試すことを優先している。  
    特にiOSではカメラ、写真、位置情報、MapKitなどのネイティブ機能を利用する可能性があるため。
- Flaskでいいの？
  - 現時点のプロトタイプではFlaskを採用している。  
    Pythonで実装でき、必要なREST APIを比較的小さな構成で構築できるため。  
    規模や要件が明確になった段階で、Flaskを継続するかFastAPI等を含めて判断する。
- PostgreSQLを使う理由は？
  - 個体・写真・観察記録・位置情報など、複数のデータ間の関係を扱うことを想定しているため、リレーショナルデータベースを採用している。  
    PostgreSQLはGISとの連携も可能なので、将来的に位置情報を本格的に扱う場合にも対応しやすい。
- 画像はどこに保存する？
  - 現在のプロトタイプではFlask側のローカルストレージに保存している。  
    本番環境ではデータベースとは分離し、S3等のオブジェクトストレージへの保存を想定している。
- Vercel / Railway / S3をどう使い分ける？
  ```
  Next.js       → Vercel
  Flask         → Railway
  PostgreSQL    → Railway等のマネージドDB
  画像           → S3
  ```
- 認証はどうする？
  - 現在のプロトタイプでは未実装。  
    誰が何をできるかという要件を確認した上で、認証方式・権限管理を決定する。
- セキュリティは？
  - プロトタイプでは最低限の構成。  
    本番ではHTTPS、認証・認可、入力値検証、画像アップロード時のファイル検証、アクセス制御、秘密情報の管理などが必要になる。
- バックアップは？
  - プロトタイプでは本格的なバックアップは未実装。  
    本番ではDBのバックアップと画像ストレージのバックアップ・冗長化を検討する。
- 個人情報は？
  - 現時点では個人情報を扱う仕様は確定していない。  
    ユーザー登録等を行う場合は、収集する情報・利用目的・公開範囲・削除方法などを要件として確認する。
